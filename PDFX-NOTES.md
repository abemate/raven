# PDF-XChange Editor 11 on Raven

This branch runs **PDF-XChange Editor 11** (the portable x64 release) under Raven. It is used as a daily PDF editor on KDE Plasma (Wayland).

> **Please read this first.** All of the code in this branch was generated by Claude (Anthropic's Claude Code). abemate is not a programmer: abemate's part was using PDF-XChange every day, reporting what broke, and testing the fixes. Nobody has reviewed the code line by line the way a human contributor would. Take it with the usual 2026-sized AI grain of salt.

## What works

- Viewing, scrolling and zooming, with the thumbnail, bookmark and comment panes.
- **Comments:** highlight, shapes, stamps, typewriter and sticky notes, then saving with annotations.
- **Forms:** filling them in, and creating fields.
- **Pages:** insert, delete, extract, move, rotate, crop, merge and split.
- **Text:** editing, search, spell check and OCR.
- **Printing** through CUPS, with landscape pages and bold or italic text.
- **File dialogs:** the desktop's own Open and Save As, through the XDG portal.
- **Drag and drop** with the desktop's file manager, in both directions.
- **Keyboard:** custom shortcuts, including Ctrl+Alt chords, and the ribbon's Alt key tips.
- **Window handling:** maximizing, tiling, and dragging a maximized window by its title bar.

## What's here

There are about 75 commits on top of `main` as of `f56b75b`. Together they touch about 95 files, adding about 7,500 lines and removing about 300. One of them is a cherry-pick of PR #140 by Raymond Bennett, with his authorship kept. Most of the others are general Raven fixes that PDF-XChange happened to expose.

Highlights:

- **Window management:**
  - WM_MOVE and WM_SIZE now come from WM_WINDOWPOSCHANGED.
  - Raven follows the compositor's maximize and restore, including restores that come without a size.
  - Update regions are clipped to the client area, and siblings repaint when a child window that covered them hides, moves or is destroyed.
  - Wayland: owned popups and dialogs, unowned tool popups placed by the program, and layered window opacity and color key.
- **Input:**
  - Ctrl+Alt+key arrives as WM_KEYDOWN, and left and right modifiers keep separate state, as on Windows.
  - The mouse wheel goes to the hovered window.
  - Host input is routed to the window's own thread, which fixes a cross-thread WM_NCHITTEST deadlock.
  - Owned dialogs keep the keyboard and hand it back when they close.
- **GDI and text:**
  - StretchDIBits and ExtTextOut honour mapping modes and world transforms.
  - Bold and italic faces are enumerated correctly.
  - GetCharacterPlacement, GetRandomRgn, ScrollDC, TransparentBlt and others are added.
  - Uniscribe and text measuring are served without stopping the guest.
- **New pieces:**
  - Printing through CUPS: printer DCs, PageSetupDlgW.
  - The XDG portal file chooser.
  - Wayland drag and drop in both directions.
  - Fault reports that say which mapping or bitmap a faulting address belongs to.
  - RAVEN_TRACE_DRAG.
- **Performance:**
  - An FlsSetValue guest fast path.
  - Wayland frame changes found by comparing rows directly instead of hashing them.

Skip the `PDFX-NOTES.md` and `README.md` commits when cherry-picking: they only describe this repository. `contrib/pdfx/` holds a personal launcher and setup script, and `scripts/native-pdfx.py` is a headless test harness for PDF-XChange. They are probably not upstream material.

## Against CONTRIBUTING.md

This branch was never meant to be a pull request, so it doesn't fully follow the guidelines. Here is where it stands, so nothing comes as a surprise when you cherry-pick.

**Commit messages: partly followed.** The first 41 commits use `type: subject`. The later ones (from "Printing through CUPS" on) have plain-sentence subjects; when cherry-picking, they would need a type, such as `fix:` for most of them and `perf:` for the FlsSetValue and Wayland frame commits. Most commits have a body that explains the reason.

**AI disclosure: not followed in the commits.** The commits credit Claude with `Co-Authored-By`, which CONTRIBUTING.md asks not to do, and they have no `Assisted-by` / `AI-Scope` trailers. The exceptions are Raymond's cherry-picked commit and the last docs commit. For all of them, the honest trailers would be:

```text
Assisted-by: Claude Code:claude-opus-5-5
AI-Scope: investigation, patch, tests and commit message, from bug reports and test runs by a non-programmer user
```

**Tests: partly followed.** 18 of the 68 commits that change code add or extend a regression test. These include the window, input, update-region, Uniscribe, key-tip, drag-restore and token fixes. The rest were checked by running PDF-XChange itself, through `scripts/native-pdfx.py` in a headless labwc/KWin session and through daily use, which is not the same thing. Some coverage gaps:
- Few tests have 32-bit callers.
- API error cases are thin, especially for the small `feat: add …` commits.

**Test results:** the full CTest suite was run in an Ubuntu 24.04 VM (MinGW-w64 13, no GPU). Failures seen there, also on `main`, so they come from the environment:
- 17 `native_d3d12_*` tests.
- `native_text_boundary`, `native_text_cli` and `native_text_pixels`.
- `native_vulkan_thunk32_tables` and `native_socket_messages_x64`.

`native_cross_window_*` is flaky (about 1 run in 10, under `-j3` only).

**Performance changes: partly followed.** The FlsSetValue, Wayland frame-comparison and Uniscribe commits give before-and-after numbers in their bodies:
- FlsSetValue: stops per second while scrolling.
- Wayland frames: milliseconds per frame.
- Uniscribe: CPU seconds for three keystrokes.

They were measured in the VM by hand, not with a scripted, reproducible workload.

**Focused pull requests and discussing large changes first:** these don't apply, since this is a branch to cherry-pick from, not a PR. Commits are mostly one fix each.

**No agent instructions, transcripts or tool configuration in the repo: followed.**

**Windows materials: followed.**
- No Windows source code, leaked material or Windows system binaries were used or inspected.
- Behaviour came from public API documentation, the MinGW-w64 headers, and watching PDF-XChange run.
- Wine was run separately as a behavioural reference, and none of its code was copied.

For transparency: to understand what PDF-XChange expected, the investigation did look at PDF-XChange's own machine code at fault and call addresses, and placed breakpoints in scratch copies of its DLLs. PDF-XChange is a third-party application, not a Windows component, and none of its code is in this branch.

**Licenses: followed.**
- No code was imported from other projects.
- The new raven-shell files (`dragdrop.c` and `pagesetup.c`) are MIT guest-adapter files like the rest of that component, and are now listed in `LICENSES.json`.
- Everything else is host-runtime code, under GPL-3.0-or-later.
- The ReactOS `.spec` files are used only through the existing ordinal generator, now pointed at two more libraries.

## About upstreaming

Nothing here needs to go upstream; this branch will keep being used as it is. It just seemed a shame for the work to sit unseen. If anything is useful, cherry-pick it, rework it, or ignore it as you see fit, keeping the AI caveat above in mind.

Thanks for Raven. Running an application as large as this natively on Wayland is quite a feat of the project.
